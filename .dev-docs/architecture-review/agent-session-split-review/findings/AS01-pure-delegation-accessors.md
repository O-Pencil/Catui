# AS01: 55 accessors 是纯委托，物理上不属于主类逻辑  ## 现象  `core/runtime/agent-session.ts` 2724 行，类体 2507 行、115 个方法。其中 **55 个方法是 `settingsManager` 的一行转发**：  ```ts getTheme(): string | undefined {   return this.settingsManager.getTheme(); } setTheme(theme: string): void {   this.settingsManager.setTheme(theme); } ```  这些方法不含任何会话逻辑——没有状态转换、没有事件、没有异常处理。它们是 settings 域的**数据访问面**，只是恰好被挂在 `AgentSession` 类上。  ## 影响  - 类体 ~55 × 4 行 ≈ 220 行纯转发代码，稀释了主类可读性 - 新 reader 需要翻过大量无信息量的样板才能找到真正的逻辑方法 - 违反项目质量指标「单文件 ~800 行上限」：文件 3.4 倍超限 - data clump 信号：同一数据面（settings）反复出现  ## 方案  把 55 个转发方法抽到 `SessionSettingsAccessors` mixin（`core/runtime/session-settings-accessors.ts`）：  ```ts export function SessionSettingsAccessors<TBase extends abstract new (...args: any[]) => SettingsManagerHost>(Base: TBase) {   return class SessionSettingsAccessorsMixin extends Base {     getTheme(): string | undefined { return this.settingsManager.getTheme(); }     // ... 55 methods   }; } ```  - 方法体原样搬移，零行为变化 - mixin 落在原型链上，公共 API 面不变 - 基类约束只要求 `{ settingsManager: SettingsManager }`，依赖方向单一  ## 验收  - [x] 55 个方法全部移出，类体减少 ~220 行 - [x] `session.getTheme()` 等调用方无感知（tsc + 测试验证） - [x] 无 public API 变化
