# Recursive Source Evolution Acceptance

status: initial release deployed; GitHub reconciliation compatibility fix under acceptance

## Implemented

- Live bounded observation, independent durable supervisor and user login service.
- Daily evidence selection, worker budgets, isolated repair and frozen reproduction.
- Offline verification, independent review, exact-head CI-gated merge.
- Restart-safe npm/GitHub release and integrity-checked managed adoption.
- Comparable post-adoption measurement, rollback and subsequent-version repair.
- CLI operations, DIP module maps, dedicated macOS containment CI.

- Actual configured model worker completed a read-only connectivity task.
- Native sandbox denied out-of-checkout and Git metadata writes.
- Real Git fixture reproduction failed on baseline and passed after source repair.
- Critical harness passed normally and inside the production offline sandbox.
- Publication recovery and installation pointer tests exercise retry/provenance.
- Final DIP, quality, static/dist package boundary, build and TypeScript gates passed.
- Integrated critical harness: 220 tests passed, zero failures, both loop evals passed.
- Remote PR checks, publication and service activation are separate delivery steps.
- PR #15 merged; 1.2.23 was published with matching registry integrity and installed.
  The login service is running and a real model session produced three observations.
- Deployment exposed legacy GitHub CLI `pr edit` requests to retired Projects
  fields. Reconciliation now updates PR metadata through the verified REST PATCH
  endpoint; this avoids blocking later retries and CI-driven repair revisions.
- Creating a release also triggers the existing tag workflow. It now reconciles
  published integrity and source SHA from release provenance before skipping its
  second publisher. Unmatched registry artifacts fail closed; new manual tags
  retain their previous build/publish path.
- CI exposed a legacy test assuming distinct millisecond usage timestamps. The
  test now identifies success/error records by outcome and verifies both artifact
  identities, preserving assertions without relying on directory enumeration order.

## Explicit limits and reopen conditions

Windows service/containment, cost-denominated budgets, retention cleanup and
dependency/schema evolution remain outside this release. Observation is heuristic;
insufficient comparable samples remain inconclusive. Reopen if an accepted patch
escapes file authority, alters a frozen test, duplicates remote publication, or
switches an unverified installation. A live naturally occurring repair requires
future user activity and is not claimed by fixture or connectivity tests.
